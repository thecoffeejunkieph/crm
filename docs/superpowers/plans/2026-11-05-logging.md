# Logging Across the App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One line per request, one per business step, DEBUG entry/exit for every service call, IDs on background work, rotating log files, and a Ref on UI error toasts.

**Architecture:** Cross-cutting pieces in `shared/`: a redactor, an access-log filter, a Spring AOP `MethodInterceptor` advisor (spring-aop is already on the classpath via spring-context; no AspectJ), and MDC for jobs. `AuditLog.record` doubles as the business-step logger. Logback gets a rolling file appender.

**Tech Stack:** Spring Boot 4 / Java 21, SLF4J + Logback, Spring AOP proxies, Boot `OutputCaptureExtension` for log assertions; React 19 UI.

**Spec:** `docs/superpowers/specs/2026-11-05-logging-design.md` (crm/crm). Branch `redesign/logging` from `phase/major_refactor_ui` in crm, and from `phase/major_refactor` in crm-dashboard-ui.

## Global Constraints

- Never in logs: passwords, secrets, tokens, TOTP/recovery codes, OTPs, cookies, `Authorization`, magic/invite/reset links, file contents. Names masked (case-insensitive, contains): `password`, `secret`, `token`, `code`, `otp`, `cookie`, `authorization`, `link`, `key` — except `idempotencyKey`.
- Emails → first letter + `***@` + domain; `tin` → `***` + last 3 digits.
- Strings cut at 200 chars; collections show ≤ 5 items plus `(+N more)`; `byte[]`/`InputStream`/`MultipartFile` → `<n bytes>`.
- Request line: `{method} {path} → {status} in {ms}ms user={id} {role} q={paramNames}`; 2xx/3xx INFO, 4xx WARN (+ `code`), 5xx ERROR (no stack here).
- Slow threshold: 500 ms → WARN `slow → {method} in {ms}ms`.
- MDC keys: `requestId`, `userId` (existing), `jobId` = `job-` + 8 hex, `job` = `Class.method`.
- Files: `${LOG_PATH:-logs}/crm.log`, daily + 100 MB rollover, `maxHistory=14`, `totalSizeCap=1GB`.
- Logging code never throws into callers; render failures log one `log-render-failed` line.
- Never commit `src/main/resources/application.properties` local change (management port) or `docker-compose.dev.yml`. Commit edits to `application.properties` only as a hunk that excludes the user's port change (`git add -p`), or put new keys in `application-dev.properties`/`-prod`/`-staging` instead — **decision: new keys go in the profile files and `logback-spring.xml`; `application.properties` is not touched.**
- Gradle via PowerShell with `$env:JAVA_TOOL_OPTIONS="-Djdk.net.unixdomain.tmpdir=C:\Users\THECOF~1\gtmp"`.

## Review Focus

1. A login or password-reset request body reaching a service as a record whose field is `newPassword` / `currentPassword` / `totp` — masked by name (test in Task 1, end-to-end in Task 5).
2. The advisor proxying a bean that is also `@Transactional` — transactions and `@Cacheable` keep working (full suite in Task 3).
3. An event listener running inside a request — keeps `requestId`, adds `jobId`, and MDC is restored to the request's values afterwards, not cleared (test in Task 3).
4. The SSE stream and actuator health not producing a line every few seconds (test in Task 2).
5. The `loggers` endpoint unreachable without admin on the management port (test in Task 4).
