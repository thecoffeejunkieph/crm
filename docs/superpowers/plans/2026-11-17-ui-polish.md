# UI Polish Bundle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the five polish items from the spec:
1. Sortable columns on every table.
2. Order search by customer name.
3. An in-page image viewer.
4. Notification timestamps.
5. Dashboard style C with "See more".

**Architecture:**
- **Backend sorting:** a shared `SortRequest` helper turns `sort=key,dir` into either a plain `Pageable` sort (own columns) or a Specification `orderBy` on a joined display column (linked names), always with an `id` tie-breaker. Each paged endpoint declares its own keys.
- **Frontend sorting:** paged tables use the existing DataTable server sort. Unpaged tables use a new `useSortedRows` hook.
- **Other items:** viewer, time formatting and dashboard parts are small `ui/` components.

**Tech Stack:** Spring Boot + JPA Specifications + JdbcTemplate (backend); React + Vite + vitest + react-hook-form (frontend).

**Spec:** `docs/superpowers/specs/2026-11-17-ui-polish-design.md`

**Sorting rules**
- Sort param format: `sort=<key>,<asc|desc>`.
- Unknown key or direction → 400 `VALIDATION_FAILED` with `field = "sort"`. This is the existing `PageQuery` behaviour; keep it.
- Linked-name keys: `customer`, `rep`, `warehouse`, `product`, `assignee`, `user`.
- Nulls sort last. `id` is the final tie-breaker on every paged endpoint.

## Review Focus

1. **Sorting by a linked name across pages.** The count query must not carry the `orderBy`, or Postgres rejects it ("must appear in GROUP BY"). Page 2 must continue the order. → Task 1, test `sortByLinkedNamePagesConsistently`.
2. **Duplicate display names.** Two customers named "Acme" must not swap places or repeat across pages, which the `id` tie-breaker guarantees. → Task 1, test `tieBreakerKeepsPagesStable`.
3. **Search text containing `%` or `_`.** Must not match everything. → Task 2, test `searchEscapesWildcards`.
4. **An image viewer list with one image.** Arrows are hidden or disabled, and ←/→ does nothing. → Task 5, test `singleImageHasNoArrows`.
5. **A notification created a few minutes before Manila midnight, viewed just after it.** Must show `Yesterday h:mm`, not today's format. → Task 6, test `crossesManilaMidnight`.

### Task 1: Backend sort infrastructure (`SortRequest`) applied to Orders and Customers

**Files:**
- Create: `shared/SortRequest.java`
- Modify: `shared/PageQuery.java` (keep `toPageable` for callers not yet migrated), `sales/OrderService.java` (list), `customers/Customers.java` (list)
- Test: `src/test/java/.../shared/SortRequestIT.java`, plus additions to `OrdersIT` and `CustomersIT` (or whatever the customers list IT is called)

**Interfaces:**
- Produces:
  - `public record SortRequest<T>(Pageable pageable, Specification<T> orderSpec)`
  - `public static <T> SortRequest<T> SortRequest.of(PageQuery page, Set<String> ownFields, Map<String, Join<T>> joins, Sort defaultSort)`
  - `public record Join<T>(String table, String idColumnOnRoot, String displayColumn)`. This joins by a subquery: `(select <displayColumn> from <table> x where x.id = root.<idColumnOnRoot>)`.
- Behaviour:
  - **Own field:** `pageable` is sorted by `field dir, id asc`, and `orderSpec` is a no-op.
  - **Join key:** `pageable` is unsorted, and `orderSpec` adds `query.orderBy(cb.asc/desc(<subquery or join>), cb.asc(root.get("id")))`. It does this only when `query.getResultType() != Long.class`, so count queries carry no order. Nulls go last, which is Postgres's default for asc; for desc add an explicit nulls-last expression.
  - **Callers:** combine with `spec.and(sort.orderSpec())` and `repo.findAll(spec, sort.pageable())`.
- Keys for this task:
  - Orders: `number, status, paymentStatus, total, updatedAt, createdAt, dueDate` plus joins `customer → customer.display_name via customer_id` and `rep → app_user.display_name (or name) via rep_id`.
  - Customers: every column on CustomersPage plus join `rep` via `assigned_rep_id`.

- Sales hero: net sales vs its own target. Use `spark` only if SalesInsights carries a monthly series.
- Warehouse hero: orders to pick.
