# Leads (F-120) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Leads with an admin-managed source list, status workflow, duplicate warning and conversion to a new or existing customer.

**Architecture:** `customers` gains the shared `lead_source` list (it owns it, because `leads` depends on `customers` and not the reverse) plus two public methods for conversion and one for duplicate matching. New Spring Modulith module `leads` owns `lead`, its scopes, status rules and conversion. UI adds `features/leads`, an admin Lead sources page, and turns the customer form's Source into a pick-list.

**Tech Stack:** Spring Boot 4 / Java 21, Postgres 17 + Flyway, Testcontainers `@IntegrationTest`, MockMvc; React 19, TanStack Query 5, react-hook-form + zod, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-05-leads-design.md` (crm/crm, 3dcd28a). Repos: crm/crm branch `phase/major_refactor_ui`, crm-dashboard-ui branch `phase/major_refactor` (work on `redesign/leads` in each).

## Global Constraints

- One migration `V14__leads.sql` holds `lead_source`, `lead`, the customer columns and the backfill.
- Seeded sources, in this order: Walk-in, Referral, Facebook, Website, Phone call, Trade show.
- Lead statuses: `NEW, CONTACTED, QUALIFIED, LOST, CONVERTED`. Open = NEW + CONTACTED + QUALIFIED.
- Lengths: source name 1–60; contact_name 1–120; company ≤160; phone ≤40; email ≤254; social ≤1000; interest ≤2000; notes ≤4000; lost_reason 1–500.
- Error codes (`shared/ErrorCode`): `LEAD_CONVERTED` 409, `LEAD_LOST` 409, `LEAD_SOURCE_EXISTS` 409, `LEAD_LOST_REASON` 422, `LEAD_CONTACT_REQUIRED` 422, `LEAD_SOURCE_ARCHIVED` 422 (422 = `UNPROCESSABLE_CONTENT`, as existing codes). Stale version → existing `STALE_VERSION`. Hidden → `NOT_FOUND`.
- Audit actions (`audit/AuditAction`): `LEAD_CREATED, LEAD_UPDATED, LEAD_STATUS_CHANGED, LEAD_ASSIGNED, LEAD_CONVERTED, LEAD_SOURCE_ADDED, LEAD_SOURCE_RENAMED, LEAD_SOURCE_ARCHIVED, LEAD_SOURCE_RESTORED`; entity types `"LEAD"`, `"LEAD_SOURCE"`.
- `SecurityConfig`: `/api/leads`, `/api/leads/**`, `/api/lead-sources`, `/api/lead-sources/**` → `hasAnyRole("ADMIN","SALES")` (WAREHOUSE 403 before `@PreAuthorize`). Source writes are `ADMIN` via `@PreAuthorize`.
- `IdempotencyFilter.DEFAULT_PATHS` += `"/api/leads"`, `"/api/leads/*/convert"`, `"/api/lead-sources"`.
- Phone matching key: strip non-digits; a 12-digit key starting `63` becomes `0` + last 10 digits (so `+63 917 123 4567` = `0917-123-4567`). Ruling over the spec's "non-digits stripped": PH numbers are written both ways.
- Every new route in `SecurityMatrixTest`; OpenAPI snapshot refreshed with `-DupdateSnapshot=true`.
- Spec's "Settings → Lead sources" is its own admin page `/admin/lead-sources` next to Settings in the Admin nav group (the Settings page is a single form of key/values).
- Never commit `crm/crm/src/main/resources/application.properties` or `docker-compose.dev.yml`.
- Gradle: PowerShell, `$env:JAVA_TOOL_OPTIONS="-Djdk.net.unixdomain.tmpdir=C:\Users\THECOF~1\gtmp"`, `.\gradlew.bat` (scratchpad `gw.sh`).

## Review Focus

1. A rep converts by linking a customer held by another rep → 404, lead stays open, no customer touched (test in Task 6).
2. Conversion where the customer request fails validation (BUSINESS without business name) → 422 and the lead is still open, no customer row (test in Task 6).
3. Same phone typed as `+63 917 123 4567` and `0917-123-4567` → duplicate found (test in Task 5).
4. A lead whose source was archived later: editing its notes without touching the source still saves; switching to an archived source → 422 `LEAD_SOURCE_ARCHIVED` (test in Task 4; same rule for customers in Task 1).
5. Backfill of messy customer sources: `"facebook"`, `" Facebook "` land on the seeded Facebook; `"FB"` and `"fb"` become one new `FB` source; blank stays null (test in Task 1).
