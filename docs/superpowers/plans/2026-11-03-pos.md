# POS (#4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A counter screen that sells to a real customer, fully paid, from one warehouse, producing a `FULFILLED`
POS order with an `ISSUED` invoice, verified payments and `DISPATCH` movements, in one transaction.

**Architecture:** A `PosService` in `sales` chains the existing steps: `OrderService.create` → `confirm` (reserves)
→ `InvoiceService.issue` → `PaymentService.record` per tender → a new `OrderService.fulfilAtCounter` (release gate,
`Inventory.consume`, `FULFILLED`, no delivery order). The UI adds `src/features/pos/` built from the `src/ui` kit.

**Tech Stack:** Java 21, Spring Boot 4.0.6, Postgres 17, Flyway, Testcontainers (`@IntegrationTest`), MockMvc;
React + TypeScript, TanStack Query, Vitest, Playwright, `openapi-typescript` (`npm run gen:api`).

**Spec:** `docs/superpowers/specs/2026-11-02-pos-design.md`

**Repos:** backend `crm/crm` (branch `phase/major_refactor_ui`), frontend `crm-dashboard-ui` (branch
`phase/major_refactor`). Work on a new branch `redesign/pos` in each.

## Global Constraints

- A POS sale is fully paid: Σ payment `cashAmount` == order total, exactly. No withholding on POS payments.
- Per line: `discountPct` ≤ `approval.discountPercentMax` and net unit price ≥ `minUnitPrice` =
  `max(cost, price × (1 − cap/100))` (cost null → price floor only). Money rounds HALF_UP to 2 places as in
  `OrderTotals.money`.
- Cost never appears in any POS response.
- Access: `@salesPermissions.canWrite()` for checkout and proof upload, `canRead()` for the product list
  (same as orders).
- Any failure rolls back everything: no order, no reservation, no movement, invoice counter unchanged.
- Error codes (add to `shared/ErrorCode`): `POS_NOT_CONFIGURED` 409, `POS_PRICE_NOT_ALLOWED` 422,
  `POS_PAYMENT_MISMATCH` 422, `POS_OUT_OF_STOCK` 409, `POS_APPROVAL_REQUIRED` 422.
- `pos.warehouseId` setting: `0` = not configured.
- Don't touch `OrderStateMachine`, `ApprovalChecks`, `StockLedger`.

## Review Focus

1. **Double-tap Charge / network retry** → same `Idempotency-Key` returns the first sale, no second invoice.
   Pinned in Task 4 (`retryWithSameKeyReturnsSameSale`).
2. **Stock sold elsewhere between grid load and checkout** → 409 naming the product, grid refreshes, cart kept.
   Pinned in Task 4 (`outOfStockRollsBackEverything`) and Task 7 (`outOfStockNamesProducts`).
3. **Cash tendered less than its amount, or tendered on a non-cash row** → 400 on that field. Pinned in Task 4
   (`tenderedBelowAmountRejected`).
4. **Same product added twice** → client merges; server rejects duplicates with 400. Pinned in Task 4
   (`duplicateProductRejected`) and Task 6 (`addMergesSameProduct`).
5. **Warehouse in the setting is archived** → `POS_NOT_CONFIGURED`, not a 500. Pinned in Task 3
   (`archivedWarehouseIsNotConfigured`).
