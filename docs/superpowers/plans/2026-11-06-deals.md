# Deals (F-130) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deals on customers with stages, value and close date, linked quotes/orders, automatic Won on order confirmation, and list/detail/rail UI.

**Architecture:** New Spring Modulith module `deals` owns `deal` and `deal_order`. `sales` gains a public `OrderBrief` lookup and publishes `OrderConfirmed` from `OrderService.markConfirmed`; `deals` listens in the same transaction and to `CustomerReassigned`. UI adds `features/deals`, a customer rail section and an order-workspace link.

**Tech Stack:** Spring Boot 4 / Java 21, Postgres 17 + Flyway, Testcontainers `@IntegrationTest`, MockMvc; React 19, TanStack Query 5, react-hook-form + zod, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-06-deals-design.md` (crm/crm, e105c76). Repos: crm/crm `phase/major_refactor_ui`, crm-dashboard-ui `phase/major_refactor` (work on `redesign/deals` in each).

## Global Constraints

- Migration `V15__deals.sql` exactly per the spec's two tables; `deal.stage` check `IN ('DISCOVERY','PROPOSAL','NEGOTIATION','WON','LOST')`; `value numeric(14,2) CHECK (value >= 0)`; unique index on `deal_order(order_id)`.
- Stages: `DISCOVERY, PROPOSAL, NEGOTIATION, WON, LOST`; open = first three. Lengths: title 1–160, lost_reason 1–500, notes ≤ 4000.
- Error codes (`shared/ErrorCode`): `DEAL_CLOSED` 409, `DEAL_LOST_REASON` 422, `DEAL_ORDER_MISMATCH` 422, `DEAL_WON_NEEDS_ORDER` 422 (422 = `UNPROCESSABLE_CONTENT`). Stale → `STALE_VERSION`; hidden → `NOT_FOUND`.
- Audit (`audit/AuditAction`): `DEAL_CREATED, DEAL_UPDATED, DEAL_STAGE_CHANGED, DEAL_WON, DEAL_ORDER_LINKED, DEAL_ORDER_UNLINKED, DEAL_REASSIGNED`; entity type `"DEAL"`.
- `SecurityConfig`: `/api/deals`, `/api/deals/**` → `hasAnyRole("ADMIN","SALES")`. `IdempotencyFilter.DEFAULT_PATHS` += `"/api/deals"`, `"/api/deals/*/orders"`.
- Every route in `SecurityMatrixTest` (all `AS`); OpenAPI snapshot refreshed with `-DupdateSnapshot=true`.
- Lessons from F-120 that apply: `Map.of()` lookups must guard null keys; JSON `null` fields are `isEmpty()` in jsonPath, not `doesNotExist()`; create endpoints in this codebase answer 201 only where the controller says `@ResponseStatus(CREATED)` (deals: yes); a `register()`ed `<select>` whose options load later needs `key={options.length}`.
- Never commit `crm/crm/src/main/resources/application.properties` or `docker-compose.dev.yml`.
- Gradle via scratchpad `gw.sh` (PowerShell + `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:\Users\THECOF~1\gtmp`).

## Review Focus

1. A rep links an order of a customer they cannot see, or of another customer, to their deal → 422 `DEAL_ORDER_MISMATCH`, nothing linked, no leak of the order number (test in Task 3).
2. Two quotes linked to one deal and both confirmed → the deal is Won once, by the first; the second confirm leaves it unchanged and audits nothing (test in Task 4).
3. Confirming an order whose deal is Lost → deal stays Lost (test in Task 4).
4. Customer reassigned while one deal is open and one is Won → only the open one moves; the old rep then gets 404 on it (test in Task 5).
5. Summary totals with deals without a value (null) → counted, not summed as zero errors; totals in ₱ to two decimals (test in Task 1).
