# Reports (F-172) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collected-money reports by month, rep, customer and product over any date range of up to 24 months.
ADMIN sees everything; SALES sees only their own orders.

**Architecture:**
- **Backend:** one read-only endpoint in the existing `insights` module. `ReportRange` parses the range,
  `ReportQueries` holds the SQL and `ReportController` applies the scope. There is no migration and no cache.
- **Frontend:** one page in `crm-dashboard-ui/src/features/reports/`. Its state lives in the URL.

**Tech Stack:**
- **Backend:** Spring Boot 4, Java 21, NamedParameterJdbcTemplate, Testcontainers `@IntegrationTest`.
- **Frontend:** React 19, TanStack Query, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-07-reports-design.md`

## Global Constraints

- Collected = `p.cash_amount + p.withholding_amount` where `p.status = 'VERIFIED'`, dated by
  `(p.verified_at at time zone 'Asia/Manila')::date`.
- The credited rep is `sales_order.rep_id`, and the scope filters on it too. Cancelled orders still count.
- Money is rounded HALF_UP to 2 decimal places, and percentages HALF_UP to 1 decimal place.
- Range parameters:
  - `from` and `to` are inclusive Manila dates, defaulting to the first and last day of the current Manila month;
  - `to` may be at most `from.plusMonths(24).minusDays(1)`;
  - anything else is `400 REPORT_BAD_RANGE`.
- A SALES user who sends `by=rep` or `repId` gets 403 (`AccessDeniedException`). SALES never sees margin fields.
- Rows share one shape: `ReportRow(month, id, name, collected, payments, sharePct, margin, marginPct,
  linesWithoutCost)`, with unused fields null.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never commit
  `src/main/resources/application.properties`, `docker-compose.dev.yml` or `graphify-out/`.
- `/api/reports/**` is already an ADMIN and SALES URL rule in `SecurityConfig`, so no security config change is needed.

## Review Focus

1. **A payment verified at 23:30 Manila on the last day of the range.** It must count, and one verified at 00:30 the
   next day must not. The test is in Task 2.
2. **An order whose total is 0, or with no lines (shipping only).** The product report must not divide by zero, and
   shipping still goes to the Shipping row. The test is in Task 3.
3. **Two payments on the same order, both in range.** The order's lines are allocated from both, and `payments`
   counts distinct payments, not payment × line joins. The test is in Task 3, plus the payment count in Task 2's
   customer test.
4. **A rep who is no longer active but has money in range.** They still appear in the rep report, by name. The test
   is in Task 2.
5. **A SALES user opening `/reports?by=rep` from a pasted link.** The page must not request `by=rep` and should fall
   back to By month. The test is in Task 4.

### Task 3: Product report with pro-rata split

**Files:**
- Modify: `ReportQueries.java` (adds the PRODUCT branch)
- Test: `src/test/java/ph/thecoffeejunkie/crm/insights/ReportsProductIT.java`

**Interfaces:**
- Consumes: Task 2's `ReportQueries.report`, `ReportRow` and `RepFilter`.
- Produces: `by=product` rows. `id` is the product id, and is null for the row named "Shipping".

**Allocation SQL:** this decides how each payment is spread over products.

```sql
with paid as (select p.id pid, o.id oid, o.total, o.shipping_fee, (p.cash_amount + p.withholding_amount) amt
              from payment p join sales_order o on o.id = p.order_id
              where <same filter as Task 2> and o.total > 0)
select pr.id, pr.name,
       sum(paid.amt * l.line_total / paid.total) collected,
       sum(paid.amt * (l.line_total - l.unit_cost * l.qty) / paid.total)
           filter (where l.unit_cost is not null and l.line_total > 0) margin,
       sum(paid.amt * l.line_total / paid.total) filter (where l.unit_cost is not null and l.line_total > 0) costed,
       count(distinct l.id) filter (where l.unit_cost is null) missing
from paid join order_line l on l.order_id = paid.oid join product pr on pr.id = l.product_id
group by pr.id, pr.name
-- Shipping: select sum(amt * shipping_fee / total) from paid
```

`margin × line_total / line_total` simplifies to the form above. `marginPct = margin / costed × 100`, and it's null when `costed` is 0. Rows are rounded after summing. Drop rows with collected 0. Add the Shipping row when it's above 0, then sort by collected desc. For SALES (`withCost == false`), margin, marginPct and linesWithoutCost are null.
